Context

Marly started with a monthly webinar campaign at my day job in early 2026. It took close to two months to produce about 25 ads: rounds of revisions, constant confusion, and output that kept drifting from the brief. Since these campaigns run nearly every month, the process should have been a playbook, but it never was.

So I tested whether an AI workflow could take over the repetitive part. Marly is that test: a pipeline that takes a brand kit and a brief and turns them into animated HTML5 ad sets, close to on-brand from the first draft. I’m the creative director, the pipeline architect and the final QA gate.

Problem

The slow part of ad production isn’t the craft. It’s the early rounds: working out layout, sizes, copy limits and motion before anyone can react to anything.

The existing options don’t fix that. Enterprise platforms like Celtra automate at scale but assume someone else is making the creative. In my market research, agencies charged $350–1,500 per ad set, took upwards of five weeks, and restarted the file handoff every campaign, so nothing built up. DIY tools produce output that looks like Canva.

Solution

Marly treats an ad set like a component library. Brand decisions get encoded once, and every size is an instance of them. Layout, sizes, copy limits and animation sequences are all tokenized, so whatever shape the brief arrives in, the first draft comes out close to on-brand.

DECISION FORK 1

Automate the whole ad, or just the first draft?

The tempting version generates finished creative: brief in, ad set out. Bigger ceiling, better pitch, and it’s what most people in this space are building. It also produces average work.

Marly automates the first draft and the build. The AI turns the brief into a V1, I mark it up in Figma as creative direction, and the pipeline builds from my direction. Ghia’s pastel restraint and Magic Spoon’s maximalism come out of the same infrastructure.

Speculative work. Not affiliated with, commissioned by, or endorsed by the brands shown.

Three tiers, each building on the one below

Tier 1 is the skeleton every build inherits. Tier 2 swaps in a brand’s tokens, so its files pick up Tier 1 updates. Tier 3 is the campaign spec Opus writes before Code starts. That’s why a brand’s second campaign is faster than its first.

Two phases, one gate

Phase I is planning. Opus writes the plan, and Code can’t start until every stage in it is accounted for.

Phase II is building. Code generates the HTML and deploys it. Then nine checks run against the files that actually landed, not Code’s report of what it did: paths, file weights, IAB compliance, animation tokens; any failure alerts the creative director and stops the build.

Animation intent locked at the brief

The campaign type sets the animation sequence. The brand’s energy, from its CLAUDE.md file, picks which animation token runs inside it. Ghia’s retargeting set opens on a product already in frame with a slow fade. Graza’s mayo launch leads with squeeze-bottle physics.

Surface effects sit on their own layer above the animation: scrims, feathered edges, glows, shimmer; Gorjana jewelry gets a warm gold shimmer because the product is brass while Graza olive oil gets none.

DECISION FORK 2

When the brief and the Figma file disagree, which one wins?

Halfway through Tumblerware the direction flipped. The brief said dark product demo. The creative direction pass came back as a light, multi-product carousel. In a normal handoff that’s a conversation. A pipeline has nobody in the loop to have it, so it needs a rule that gives the same answer every time: after the creative direction pass, Figma wins.

Treating the brief as the contract would also be defensible, since it’s what gets signed off. What matters is that the rule exists before you need it; a brief can go stale without anyone noticing, so anything that has to survive a reversal gets written into the architecture instead. That’s why Architecture B (CSS token classes and vanilla JS, no GSAP, no runtime) gets checked on every build.

Learning

On Aura and Echo, other people used what I built, so feedback came through them. On Marly I’m the author, the user and the QA gate at once. There’s no engineer to blame for an inconsistency. The nine-check verify step exists because I couldn’t trust my own review at 2am.

While the workflow works, nobody’s bought it. I think it’s worth more inside a company that runs campaigns every month than as a studio chasing clients, which is the problem it was built to solve in the first place.

Scope

Solo venture: creative direction, design system, pipeline architecture, build and QA.
